## ✨ ما الذي يميز هذه المنصة؟

هذا المشروع ليس مجرد قالب تجارة إلكترونية عادي. إنه **منصة قابلة للتخصيص بالكامل بشعارك الخاص (White-label)** مصممة لتقديم أقصى درجات المرونة والمرونة في واجهة المستخدم (UI/UX) مباشرةً من لوحة الإدارة، لتناسب أي علامة تجارية. 

* **تحكم كامل في التصميم:** يمكن للمسؤولين تغيير الهوية البصرية بسهولة دون المساس بالكود. يمكنك تغيير الشعارات، وتحديث لوحة الألوان بالكامل، وتعديل الخطوط لتتناسب تماماً مع هوية علامتك التجارية في غضون ثوانٍ.
* **تخطيطات مرنة (Layouts):** يمكن تغيير ترتيب القوائم في واجهة المتجر بكل أريحية. يُمكن تكوين الرأس (Header) والتذييل (Footer) حسب الرغبة. وبالنسبة للافتات الإعلانية (Banners)، يمكنك الاختيار بين اللافتات المتحركة المتمررة أو القطع الثابتة بناءً على رؤيتك.
* **تخصيص واجهة المتجر:** الصفحة الرئيسية وواجهة العرض مصممتان بنظام النماذج (Modular). أقسام مثل "الفئات الرئيسية"، "آراء العملاء"، و "النشرات الإخبارية" يمكن تفعيلها، تعطيلها، أو تخصيصها و ترتيبها بالكامل.
* **دعم اللغات المتعددة بشكل عميق (7 لغات):** تعمل جميع التعديلات التصميمية المذكورة سابقًا، إلى جانب جميع بيانات المنتجات والفئات، بشكل ديناميكي كامل ومدمج عبر 7 لغات مسبقة التكوين. بمجرد إضافة منتج جديد، يمكن للمسؤولين وضع ترجمات له للغات السبعة عبر نظام "لوحة تحكم الترجمات"، لضمان تجربة تسوق عالمية ومريحة في كل بقاع الأرض.

## البنية المعمارية

هذه المنصة تستند إلى "بنية أحادية نموذجية" (Modular Monolith) مع فواصل قوية تتبع "الهندسة النظيفة" (Clean Architecture). إضافة لنموذج (CQRS) المدار من مكتبة MediatR ونمط التصميم المدفوع بالمجال (Domain-Driven Design). ولا تُنتهك قوانين البنية الداخلية بفضل مقيدات المترجم الصلبة المطبقة بـ `NetArchTest.Rules`.

### التصميم المعماري متعدد اللغات

من أجل إطلاق منصات "الوايت ليبل" بدون ارتهان واكواد ملتوية، قمنا بفصل مسميات المنتجات والفئات في جداول ترجمات مستقلة تماماً وموازية للقواعد الأساسية (`ProductTranslations`, `CategoryTranslations`). ويتم ربطها بواسطة سلسلة تعريف مزدوجة `(EntityId, LanguageCode)`. حيث يُلغى هنا ما يسمى "باللغة الجذرية في الشيفرات (Hardcoded)" — كل لغة معتمدة تُعامل باحترام ومساواة مع اللغات الأخرى.

وضمن إعدادات `appsettings.json`, نقوم بتعريف خاصية `DefaultLanguage` و التي تحدد لغة الإنقاذ الأساسية (للزوّار غير المحددين). لو كانت منصتك مركزة في السعودية فتضع القيم: `DefaultLanguage: "ar"`. مما يجعل اللغة الأم للإدارة والسيرفر عربية، وبعدها يمكن وضع مرادفات اللغات الألمانية وغيرها براحة تامة.

هذا المبدأ يحقق مفهوم الـ "White Label" بكامل رونقه ويتيح لك تصيير برمجياتك عالمياً بدون خدش سطرٍ واحد في النواة المركزية للبرنامج!

### المجالات المحددة (Bounded Contexts)

| المجال | عناصر التجارة والمجال الأساسية | القيود غير القابلة للكسر (الإينفاريانت) |
|---------|-----------------|----------------|
| **قوائم التسوق** | المنتج الصنف، وحدات المعيار المكتلية | قواعد المال لا يمكن أن تكسر حاجز الـ 0 أو تخترقه للسالب. كذلك مخزونات السلع، والقانون الشجري للأصناف. |
| **سلال الرغبات** | السلة الخاصة ، الأغراض بالسلة | لقطة ثابتة من قيمة السعر (تمنع صدمات الدفع من التغيرات بالسيرفر لاحقاً). تقبل الكسور للأوزان (اللتر الكيلو جرامات).  |
| **سجل الطلبيات** | الطلبيات المحجوزة، فروع الطرود المحددة | أوقات الرحيل والحدود المعيارية لرحلة الطرد (معلق &rarr; تم القبض &rarr; تتم التجهيزات &rarr; في الطريق &rarr; اكتمل أو محطم/ملغي). |
| **مدفوعات الزبائن** | سجل التفاعل البنكي | قوانين الامتناع عن السداد المزدوج لأصحاب الأيدي المرتجفة وقت الدفع! مبني على فكر (IdempotencyKey) كقفل مانع للدفع مرتين. |
| **الهويات الشخصية**| المستخدم المسجل | تغليف الأرقام السرية (PBKDF2) المزدوج. التمرير الخفي للـ HTTP-Cookie لإنعاش التوكن بشكل مخفي وأمن تماماً (Refresh Rotation)! |
| **دروج المفضلة**  | أماني المسجلين المشتهاة | حراسة تامة لمنع إرهاق قواعد البيانات بالنسخ المكررة لطلب نفس المسجل مرتين من المنتج للمفضلة! |

### اتجاه الاعتماديات وتسلسل التوجيه 

```text
المجال (Domain)   <- (الاستقلال المطلق ـ خلو من أي نداءات خارجية)
التطبيقات         <- المجال Domainحصراً
بناء البيانات     <- المجال Domain حصراً وباحترام لمقاييسه
الخدمات الفرعية   <- التطبيقات , ونواة المجال
قسم API           <- التطبيقات, البيانات , وتوابع السيرفرات الفرعية الأخرى
```

> البنية الصلبة للبيانات EF Core لا تمارس أي سيطرة تذكر أو إملاء قيود واشتراطات على عاتق طبقة الـApplication. المعايير والشروط الصارمة تخلق في قلب "Domain Layer" وتقوم الطبقات بتنفيذها إجبارياً مما يولد مصطلح "عكس اتجاه الرقابة Inversion of Control" الحامي للمشاريع الكبيرة!

## 🚀 كيفية الإعداد والتشغيل

وفرنا أسلوبين بارعين لتشغيل المنصة حسب الظروف والقدرات، إن كنت تود تصفح الواجهات الرائعة بصرياً في ثوانٍ لاستعراضه للزبائن دون حرق أعصابك في نصب السيرفرات والأدوات المعقدة اذهب باتجاه الخيار الأول ذو **البيانات الوهمية الشبيهة بالواقع (Mock Data)**. إما ان اتجهت طموحاتك لتبني واختبار هذا الوحش التقني في خوادم حقيقية صلبة لتجربة العصب كاملاً, فالتزم باتجاه الخط الثاني نحو الـ **Full Stack Integral Setup**!

### الخيار  1 : الإقلاع البصري الاستعراضي السريع ("Mock Data") ⚡
يولد هذا الخيار عالمـاً حيوياً للواجهة المعتمدة على **(Frontend SPA) بمفردها**. حيث يتخذ البرنامج شكل المتصل بقواعد بيانات لكن بصورة محاكية محلياً ومؤقته بالمتصفح!  بفضله ستتلمس التدويرات البصرية و أزرار تغيير اللغات والصفحات وعمل السلة بدون تجهيز سيرفرات مكلفة!
 
```bash
# 1. اسحب نسخة من ملفات الواجهة للويب
git clone <repo-url>
cd ECommerce/src/ECommerce.Web

# 2. قم بتمرير أمر جلب الأدوات الداعمة للرياكت والتايب سكريبت  
npm install

# 3. افرض القيود وأقر للمحرك بالاعتماد على النظام المغلق الوهمي
# ابحث عن .env.development.local  وألزم المحرك بـالسطر الواضح :
# VITE_USE_MOCK_API=true

# 4. أعطي إشارة الانطلاق للمتصفح 
npm run dev
```

*انتهت المهمة!* اذهب برحلة لمشاهدة الانتاج الحي على رابط منصة المحلي Localhost المطبوع في الطرفية وتمتع بالمناظر التجارية وقم بتغيير الألوان براحة تامة.

### الخيار 2 : إيقاظ العصب التشغيلي الكامل (Full Backend .NET10 + SQL + REDIS ) 🏗️
أوامر صارمة لإخراج المارد التقني وتفعيله بقوة PostgreSQL والريديس القوية للإحتكاك المباشر الحي بالتجارة.

#### القسم A : إنشاء المزارع والبيانات (عبر الدوكر Docker)
اخرج من الكهف وحشين عظيمين بضغطة سطرين : 
```bash
# الصخرة العظيمة PostgreSQL الحاوية للداتا الفعلية 
docker run -d --name ecommerce-db -e POSTGRES_USER=postgresUser -e POSTGRES_PASSWORD=postgresPassword -e POSTGRES_DB=ECommerceDb -p 5432:5432 postgres:16-alpine

# عداء التحمل السريع للطلبات (كاش الريديس) 
docker run -d --name ecommerce-redis -p 6379:6379 redis:7-alpine
```

#### القسم B : إستخراج الأوامر لسيرفر الدوت نت المركزي 
```bash
# عُد للصفحات الأولى للملف الرئيس
cd ECommerce

# أعط الأوامر للبناء الأولي في البوستجريس للجداول والأعمدة الفارغة (Migrations Setup) 
dotnet ef database update --project src/ECommerce.Persistence --startup-project src/ECommerce.API

# شَـغّـــــــــل 
dotnet run --project src/ECommerce.API
```
*إنجاز رهيب! إن لم ينفجر البناء في وجهك فهذا يعني أنك فعلتها.. تفقد الـ Swagger الخاص بالمشروع  والمتاح عبر العبور الآمن المفتوح هنا : `https://localhost:5001/swagger`*

#### القسم C : الارتباط الاستراتيجي بالفرونت اند (React Web SPA)
أثناء عمل السيرفر افتح موجه أوامر جديد:
```bash
cd ECommerce/src/ECommerce.Web

# استيراد الاعتماديات الخاصة بالويب كما في الخيار الأول 
npm install

# إلغاء قيود اللعب الاستعراضي والارتباط بقوة الصخر العتيد لـ(السيرفر)
# افتح .env.development.local وعدل :
# VITE_USE_MOCK_API=false
# VITE_API_BASE_URL=https://localhost:5001

# ابدأ التفعيل و الاستقطاب 
npm run dev
```

*🎉 نهنئك. مشروع (البنية الأحادية النموذجية الشامله) اكتمل ومرتبط بسلاسة بكل مراحله التقنية!*

## الأمان والحراسات المشددة الأمنية 

| نوع الدرع | التعليق الدقيق والتوضيح |
|---------|----------------|
| التدقيق والفصل الهوياتي | تم تحصين أمان العميل عبر تخزين التوكن حصرياً في **httpOnly secure cookies**; أي محاولة من مخترق للسرقة عبر تخزين المتصفح LocalStorage ستجد الابواب موصودة ومحطمه بقوة المعايير. |
| تبديلات الشيفرة الإجبارية (الروتيشن) | التوكنات تنتهي صلاحياتها بوقت قصير .. وتلد غيرها بصورة دورية مخفية لحجب الفرصة عن من يطمع بها. |
| قصر عمر الدخول المؤقت  | يملك كل مستخدم 15 دقيقة قصيرة للأماد (من التوكن المؤقت). ولن يتم السماح للانحرافات الساعية في الكمبيوتر (Clock Skew Validation).|
| سرداب التشفير | ارقام السر محمية بدرع عظيم الـ PBKDF2 ، والمطروق لـ 100 ألف طرقة تأكيدية متعبه للحاسبات (SHA-256 Iterations) |
| الصندوق المالي المقفل | المنصة **لا تحتفظ ولا ترى ولا تكتب أي داتا تتعلق بالبطاقات الائتمانية للمشتري!** تعتمد المنصة على اصدار سندات عبورية للبنك كضامن (Tokenizations). |
| مانع الحماقات وتكرار السحب | عبر توليفة عبقرية تتضمن :  `(OrderId, IdempotencyKey)`. لو حدث خطأ بـ جهاز الزبون وضغط الشراء 50 مـرة متكررة.. فستموت ال 49 وتنفذ العملية الفردية الأساسية الأولى فقط! لا خوف من عمليات الصرف المزدوجة بمتجرنا ابداً! |
| مصادات السيول البشرية و التصديات (Limits) | الحراس الآليين بالواجهة تمنع التدفق (DDOS) العنيفة والمشبوهة بمبدأ صارم للتحطيم الفوري عبر : FixedWindow  ولا تعطي سوى 100 طرقة بالدقيقة فقط (100 Requests/min Limit) للعنوان الواحد IP ! |
| العزل السياسي وتصفية الزوار (CORS) | المواقع الصليقة للنجاة من التحطيم تتواجد في طابور (Whitelist). غيرها من النطاقات أو السيرفرات المتلصصة تأخذ طرداً مباشراً بلا جدال! |
| التحريم القطعي لحرق الداتا وتخريبها | ميزة "الحذف الرحيم Soft-Delete".. لا يستطيع المدير مهما بلغ جنونه او غضبه أن يحذف الدليل الملموس من سيرفراتالSQL. هو فقط يقوم بتغطيته بوشاح ووسم IsDeleted لكنها في الباطن لازالت محفوظة كدليل قانوني ومرجع! |
| واجهات التجسس وحائط الدخان (UX Bluff) | حتى وإن قام شخص باصطناع صفحة واجهة (متواطئة) لتقيم عمليات ادمن.. فالسيرفر سيرفضها في رمشة عين بل ويطردها من أسواره! القرارات السيادية جميعها **في الباطن سيرفريّة Backend-based** ولن يعتمد السيرفر على خُدَع المتصفحات و React SPA. |
| الحصن الحصين للبطائن الإدارية | لا يمكن لأي حركة أن تشق طريقها لاكواد الادمن الحساسة بدون التصاريح الخرسانية  المنيعة  : `[Authorize(Roles = "Admin")]`|
