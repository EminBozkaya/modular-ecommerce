## ✨ Что выделяет эту платформу?

Этот проект — не просто очередной шаблон электронной коммерции; это **полностью настраиваемая платформа White-Label**, разработанная для обеспечения максимальной гибкости UI/UX напрямую через панель администратора.

* **Полный контроль над дизайном:** Администраторы могут легко и мгновенно менять визуальный стиль без необходимости лезть в код. Вы можете менять логотипы, обновлять глобальную цветовую палитру и настраивать шрифты, чтобы проект идеально соответствовал фирменному стилю любого бренда.
* **Гибкие макеты:** Меню витрины можно свободно переставлять. Области заголовка (Header) и подвала (Footer) легко настраиваются по желанию, а рекламные баннеры могут быть отключены или представлены в виде бегущих строк, либо неподвижных блоков.
* **Кастомизация витрины:** Главная страница и витрина спроектированы по модульному принципу. Такие блоки как: Основные Категории, Отзывы клиентов и Раздел Новостей, могут быть включены, отключены или полностью кастомизированы.
* **Многоязыковая поддержка (7 языков):** Каждая упомянутая визуальная настройка, а также все базы товаров и категорий, могут работать на 7 языках одновременно. Как только добавляется новый продукт, менеджер вписывает переводы для 7 языков прямо в панели администратора, получая продукт, мгновенно готовый к продаже в международном масштабе.

## Архитектура

Структура представляет собой "Модульный Монолит" с жестким соблюдением правил Чистой Архитектуры (Clean Architecture), CQRS (командно-запросная ответственность через MediatR) и DDD (Предметно-Ориентированное Проектирование). Запросы зависимостей постоянно анализируются правилами на этапе компиляции посредством библиотеки `NetArchTest.Rules`.

### Мультиязычный агностический дизайн

Удобство перевода всех товаров без жестко-запрограммированного 'Основного' языка. Вместо этого все слова и рекламные материалы хранятся в отдельных независимых базах для перевода (`ProductTranslations`, `CategoryTranslations`), с использованием составного ключа `(EntityId, LanguageCode)`. В архитектуре нет языка "по умолчанию" на уровне кода – любой язык является полноправным и равным остальным.  

Однако в `appsettings.json` присутствует переменная `DefaultLanguage`, чтобы определять, на какой язык сбросить страницу, если клиент зайдет с языка, для которого перевода не нашлось. Если сервер был установлен и запущен, например, в Москве, администратор выставит `DefaultLanguage: "ru"`, после чего можно добавлять русские элементы, добавлять турецкие или немецкие можно позже из редактора. 

Такой модульный подход делает из программы "Белый Лист" (White Label), пригодный к глобальному деплою по всему миру, без необходимости изменять внутренние корни кода.

### Ограниченные контексты (Bounded Contexts)

| Контекст | Доменные атрибуты бизнес-логики | Критические Правила (Инварианты) |
|---------|-----------------|----------------|
| **Каталог** | Продукт, Категория, Единица величины (Unit) | Финансы (Money) непоколебимы числом >0, С톡 запасов >= 0. |
| **Корзина** | Содержимое Корзины, Записка о Товаре | Ценник копируется, предотвращая "внеплановый инфляционный скачок" при платеже. Приём дробных единиц по весу. |
| **Заказы** | Ордер (Заказные листы), Товарные пункты | Движение машины статусов: в ожидании &rarr; оплочено &rarr; процесс обработки &rarr; отправлено &rarr; доставлено / отмена. |
| **Платежи** | Платёжная Учетная Запись | Пресечение ошибки дрожащих рук покупателя (Двойной Клик / Idempotency) уникальной записью `(OrderId, IdempotencyKey)`. |
| **Личность**| AppUser | Шифовка PBKDF2; защита от шпионажа через httpOnly cookie и бесконечное ротационное обновление Refresh Token подлинника. |
| **Избранное** | Товар под Залог Памяти | Нельзя заносить один и тот же бренд 2 раза одному и тому же профилю. |

### Направление зависимостей

```text
Domain         <- (Сама независимость -- Жизнь без указаний извне)
Application    <- Domain 
Persistence    <- Domain (Строго поклоняется правилам Домена)
Infrastructure <- Domain, Application
API            <- Application, Persistence, Infrastructure
```

> Базы Персистентности (наш EF Core Database) никогда и ни при каких обстоятельствах не влияют на логику Application (Слоя приложения). Правила игры (Repositories Interface) пишутся внутри неприкасаемого Доменного слоя `ECommerce.Domain`, а реализовываться им положено в `ECommerce.Persistence`. Данный ход нарекается Величайшей Инверсией Контроля Систем.

## 🚀 Как настроить и запустить

Предлагаем на выбор два способа запустить эту систему онлайн. Первый для тех, кто хочет на скорую руку визуально оценить анимации, язык дизайна и кнопки навигации в браузерном пространстве, избегая головной боли с поднятием баз - используйте **Mock Data Режим** (Местный эмулятор). Для архитекторов и желающих убедиться в работоспособности микроядра, монолита, баз и сервера "на полную катушку" пожалуйте к инсталлятору **Полноценный Сервер (Full Stack).**

### Вариант 1: Мгновенный Визуальный Старт ("Режим Mock-Data") ⚡
В этом состоянии мы инициализируем **только лишь одну Фасадную React-модель**. Сервер и все его SQL базы просто эмулируются (фейкуются) в оперативной памяти компьютера в фоновом режиме. Вы сможете листать товары, щелкать на все 7 языковых модулей, класть продукты в корзины и визуально перенастраивать дизайн меню из админки - не открывая даже конфигуратор SQL баз. 

```bash
# 1. Скачай клон проекта 
git clone <repo-url>
cd ECommerce/src/ECommerce.Web

# 2. Установи внешние модули в проект 
npm install

# 3. Передай категорический Запрет на Поиск Реального Сервера!
# Загляни в .env.development.local и четко пропиши:
# VITE_USE_MOCK_API=true

# 4. Да начнется процесс..
npm run dev
```

*Шедевр запущен!* Переходи по предложенному Vite адресу ссылкой в браузере Localhost и наслаждайся путешествием по Электронной Коммерции.

### Вариант 2: Запуск Абсолютной Архитектуры (Бэкенд .NET10 + БАЗЫ + Кэш) 🏗️
Здесь мы поднимаем из пепла исполинские базы PostgreSQL вместе со сверх-быстрыми резервуарами Redis, чтобы живая API-линия .NET 10 соединила себя с нашим визуальным интерфейсом на React. Работаем засучив рукава. 

#### Часть A : Рождение Данных (Контейнеры Docker)
Достанем и раскроем пакеты PostgreSQL и Redis:
```bash
# Пробуждаем основного хранителя - Postgres
docker run -d --name ecommerce-db -e POSTGRES_USER=postgresUser -e POSTGRES_PASSWORD=postgresPassword -e POSTGRES_DB=ECommerceDb -p 5432:5432 postgres:16-alpine

# Пробуждаем стража кэш-памяти - Redis
docker run -d --name ecommerce-redis -p 6379:6379 redis:7-alpine
```

#### Часть B: Вдох В Бэкенд .NET
```bash
# Заходим в главную папку всего проекта 
cd ECommerce

# Заливаем схемы, чертежи и фундамент базы в мозг PostgreSQL. (Подождать пока все зальётся)
dotnet ef database update --project src/ECommerce.Persistence --startup-project src/ECommerce.API

# ПУСК МОТОРА!
dotnet run --project src/ECommerce.API
```
*Великолепно! Если руки были прямыми, вас немедленно ожидает рабочая табличка Swagger, расположенная здесь `https://localhost:5001/swagger`*

## Безопасность

| Мера Обороны | Механизм |
|---------|----------------|
| Идентификация "Свой - Чужой" | Опознаватель JWT работает скрыто в тенях через **httpOnly secure cookies**; Оставление отпечатков сессии во внешних LocalStorage карается удушением архитектуры . |
| Карусель Авторизаций (Rotation) | Ключ перегорает как лампочка каждый раз в конце хода, рождая новый Refresh Token для безопасности от слежки. |
| Срок Годности (Lifetime Token) | Полномочия длятся ровно 15 минут. Никаких поблажек для зависших часов "Clock Skew Validation". |
| Хранение Ключей(Паролей) | Хранилище Форта Нокс посредством PBKDF2 алгоритмики . Встряхивается до бетона в 100 тысяч слоев (SHA-256 Iterations) |
| Инкасаторские Дела (Payment Sec) | **Никаких Записей Чужих Банковских Даных!**. Трансферты работают только на токено-обмене квитанциями (Provider Tokenization Approach) . |
| Амортизатор Клиентской Паники (Idempotency) | Уникальная Индексация `(OrderId, IdempotencyKey)`. Если Клиент-Безумец решит нажимать на "ОПЛАТИТЬ" 56 раз за 1 секунду по одной корзине покупок... Данная защита заблокирует 55 попыток, и проведет только ПЕРВЫЙ платеж. Спасайте кошельки. |
| Контроль Толпы (Rate Limiter) | Защитный барьер отклоняет любую DDоS попытку или штурм 1 айпи-шником : Ограничение FixedWindow Limit - не больше 100 запросов в минуту от одного бойца!   |
| Фильтр На Границе CORS | Только те, кто вписан в Высший Реестр Доверенных (Whitlist) смогут обменяться печеньками Cookie через границу Базы. Остальным - Красный Свет. |
| Принцип "Рукописей, которые не горят" | Мягкое Подавляющее Удаление "Soft-Delete System". То, что администратор "стер", на самом деле никогда **не удаляется** технически. Вся база SQL останется целой, данные просто закроются Флагом IsDeleted. |
| Блеф Интерфейса Клиента SPA | Страница визуально закроет двери "Гостям" и покажет их "Админам" (UX Guards), НО!!! Подлинным Судьей и Адвокатом о правах выдачи Информации в любом случае **Остаётся СЕРВЕР (BACKEND)**. React всего-лишь послушная собака. |
| Электорат Верховенства "Админа" | Ни одна маршрутка информации к управляющей панели не пустит на борт никого без священной медали `[Authorize(Roles = "Admin")]`|
